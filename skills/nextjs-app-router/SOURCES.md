## Lightweight freshness policy

Recheck affected rows when upgrading Next/React/Claude Code, adopting a cache/runtime feature, or observing a build/runtime/activation failure. Review high-change caching, recovery APIs and loading configuration at least every three months if actively used; review slower conventions within six months. Age prompts review, not automatic rejection. Prioritize installed/bundled docs over live newest APIs.

For each review record: affected file/section, software version/config, canonical URL, upstream date or unknown, actual checked date, conclusion and checks performed. Update only the verified scope. Replace a link with a canonical successor when a move is confirmed; don't equate a transient fetch failure with a removed API. No automation is created by this policy.
