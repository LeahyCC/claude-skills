# Sources

## Taken and adapted

| Source | Read | Used for |
| --- | --- | --- |
| [DietrichGebert/ponytail](https://github.com/dietrichgebert/ponytail) `skills/ponytail/SKILL.md` and README | in full | The ladder shape: stop at the first rung that holds. Its never cut line (validation, safety, the test) became: steps the reader must follow, warnings that stop lost work, the one working example. |
| [blader/humanizer](https://github.com/blader/humanizer) `SKILL.md`, 26 patterns | pattern table in full | The sound list. Only the patterns that show up in docs were taken, 12 of 26. Its rule kept whole: never invent a fact to fill a gap. |
| Wikipedia, [Signs of AI writing](https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing) (via Humanizer) | sections behind the taken patterns | Why the tells exist: the model picks the wording that fits the widest range of readers, so docs drift to inflated, vague, staged prose. |
| [GOV.UK content design: writing for GOV.UK](https://www.gov.uk/guidance/content-design/writing-for-gov-uk) | in full | Plain words, front load the point, one idea per sentence, sentence case headings. |
| [Diataxis](https://diataxis.fr/) | framework pages | The by type split. Tutorial, how-to, reference, and explanation want different substance, which is why only layer 3 changes by type. |

## Not taken

- Humanizer patterns for personal and marketing prose (curly quotes, sales rhythm, voice matching). Docs stay neutral. A project voice sample still wins where these rules disagree.
- Ponytail modes (lite, full, ultra) and its review and audit commands. Docs get two modes only: write and trim.
- Diataxis as a filing system for a whole docs site. This skill shapes one page. Site layout is a bigger job.

## Not claimed

- No benchmark. The one worked example (190 words to 51, facts kept) is in [examples.md](./resources/examples.md). It shows the shape on one doc. It is not a measured study across many docs.
