# React performance skill tasks and acceptance criteria

Written 2026-11-01, before any model run. These cover the topics and fixes added on that date. Run each prompt against Claude with the skill and without it, as in the Next.js pilot. Score each criterion 0 or 1. One run per task is exploratory, not a statistical estimate.

## New topics

| ID | Prompt | Acceptance criteria |
| --- | --- | --- |
| P1 | "Every time I type one letter the input loses focus." Fixture: `function Form() { const [name, setName] = useState(''); function Field() { return <input value={name} onChange={e => setName(e.target.value)} /> } return <Field /> }`. | Says `Field` is a new component type on every render, so React remounts it and the input is recreated. Moves `Field` to module level and passes `value` and `onChange` as props. Does not reach for `memo`, `useCallback` or `autoFocus`. |
| P2 | "My chat socket reconnects whenever the user toggles sound." Fixture: an Effect that opens a connection for `roomId` and calls `playSound()` when `soundOn` is true, with deps `[roomId, soundOn]`. React 19.2. | Uses `useEffectEvent` for the message handler that reads `soundOn`, and leaves `[roomId]` as the deps. States that the Effect Event must not go in the deps, must be called only from the Effect, and must not be passed to children. Mentions upgrading `eslint-plugin-react-hooks`. |
| P3 | "Switching between the Editor and Preview tabs wipes the draft, and the Preview tab is slow to open the first time." Fixture: `{tab === 'editor' ? <Editor /> : <Preview />}`. React 19.2. | Wraps each panel in `<Activity mode={... ? 'visible' : 'hidden'}>`. Says hidden content keeps state and DOM, its Effects are cleaned up, and it still re-renders at lower priority. Mentions that a boundary hidden on first render pre-renders, and that only Suspense-read data loads that way. Warns not to wrap every conditional. |
| P4 | "This chart rebuilds on every parent render, and the sidebar component re-renders constantly while I resize the window." Fixture: `useEffect(..., [options])` where the parent passes an inline `options` object, and a component holding `window.innerWidth` in state only to compute `width < 768`. | Destructures the primitive fields and depends on those. Replaces the width state with a `useSyncExternalStore` hook over `matchMedia` that returns a boolean, with `subscribe` declared outside the component and a server snapshot. |
| P5 | "Profiler shows `parseDocument` running on every keystroke in this editor." Fixture: `const [doc, setDoc] = useState(parseDocument(savedJson))`, plus a handler calling `setCount(count + 1)` three times. | Changes to `useState(() => parseDocument(savedJson))` and explains the initializer runs once. Notes it must be pure and runs twice in Strict Mode dev. Switches the triple update to `setCount(c => c + 1)` and says why only one increment applied. |
| P6 | "Our analytics fires two page-load events in dev and our auth token gets invalidated." Fixture: `useEffect(() => { initAnalytics(); checkAuthToken() }, [])` in `App`. | Explains the mount Effect runs twice in development and that app-wide setup belongs to the app load. Offers a module-level `didInit` flag or module top-level code behind `typeof window !== 'undefined'`. Does not suggest removing Strict Mode. |
| P7 | "Console shows a hydration error on our order page. It's only a warning, can we ignore it?" Fixture: a Client Component rendering `new Date(iso).toLocaleTimeString()`. | Says no: React re-renders that tree on the client instead of reusing the server HTML, which costs time, and text is not patched. Makes the first client render match (fill the local time after hydration, with reserved space) and names the two-pass cost. Limits `suppressHydrationWarning` to one unavoidable element. Does not claim a precise "nearest Suspense boundary" scope as documented fact. |
| P8 | "isPending turns off too early and sometimes old search results replace new ones." Fixture: `startTransition(async () => { const r = await search(q); setResults(r) })`. | Wraps `setResults` after the `await` in another `startTransition`. Explains that transitions do not keep requests in order and React does not cancel the older one. Recommends `useActionState` or a form action, or tracking and aborting stale requests. |

## Bug fixes

| ID | Prompt | Acceptance criteria |
| --- | --- | --- |
| F1 | "Is this `useCallback` pointless? The child isn't wrapped in memo." Fixture: a callback passed to a plain child and also listed in a `useEffect` dependency array that subscribes to an event bus. | Says it still matters because the Effect depends on its identity. Lists the cases: memo child prop, Effect or Hook dependency, custom Hook return. Suggests moving the function into the Effect as a simpler option. Notes the compiler reduces the need, citing react.dev. |
| F2 | "Make the hero image load faster on our Next.js 16 site." Fixture: `<Image src={hero} alt="" priority />`. | Says `priority` is deprecated in Next 16. Prefers `loading="eager"` and `fetchPriority="high"`, keeps `preload` for when the fetch must start from the head, and never combines it with those. Does not claim `next/font` gives zero layout shift if fonts come up. |
| F3 | "Virtualize this list with react-window." Fixture: `package.json` has `react-window@^2`, and a Next.js 16 page reads `searchParams.cursor` synchronously. | Uses `List` with `rowComponent`, `rowCount`, `rowHeight`, `rowProps` and a height in `style`, with the row component at module level and typed by `RowComponentProps`. Does not use `FixedSizeList`. Types `searchParams` as a Promise and awaits it. |
| F4 | "Lazy-load the analytics panel only when the toggle is on." Next.js App Router, Client Component. | Calls `dynamic()` at module top level and renders the result conditionally. Does not call `dynamic()` inside the component. Puts `ssr: false`, if used, only in a Client Component. |
